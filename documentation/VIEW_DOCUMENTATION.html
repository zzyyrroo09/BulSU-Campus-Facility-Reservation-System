User Needs & Architectural System Options Comparison

Bulacan State University manages high-demand campus venues (CICT Amphitheater, University Gymnasium, Valencia Hall, Natividad AVR). Ad-hoc workflows previously suffered from double-bookings, unverified physical conditions upon departure, and privacy exposures where students could view details of other campus organizers.

Comparative Evaluation of Implementation Architectures
Evaluation Dimension Option A: Monolithic Django MTV (Selected) Option B: Decoupled SPA (React + Django REST API)
Architectural Complexity Optimal: Single deployable artifact, consolidated ORM session management, zero CORS latency. High: Dual runtimes, client-side state sync, cross-origin security overhead.
Strict Role Segregation High Security: Server-side RBAC decorators (@admin_required, @user_required) and middleware active-check. Moderate: Requires token claims, complex route guards, and double-validation.
Transaction & Row Locking Native: Database transactions (transaction.atomic()) and select_for_update() lock rows seamlessly. Complex: API disconnects require custom locking endpoints and race condition mitigation.
Academic Rubric Compliance 100% Compliant: Satisfies strict prohibition of automated admin packages while focusing on custom server-rendered admin views. Partial: Added frontend overhead detracts focus from custom admin ORM queries, reports, and atomic conflict logic.
Academic Justification: Option A was selected because it guarantees atomic database transaction boundaries, eliminates API serialization overhead for complex conflict checks, and allows strict compliance with the instructor's ban on auto-generated admin packages.

RUBRIC PO-n

Data Privacy Act (RA 10173) & Ethical Safeguards

Privacy Safeguard Rule in Student Schedule View

When basic students inspect facility availability, the system sanitizes reservation data. Other students' names, departments, contact numbers, event titles, and notes are completely scrubbed from the DOM. Time blocks are rendered generically as "Occupied / Reserved Slot", preventing unauthorized profiling and surveillance under RA 10173.

Session-Level Revocation & RBAC Integrity

Account deactivation does not rely solely on database flags. Custom middleware (AccountActiveCheckMiddleware) intercepts every incoming request in real time. If an administrator deactivates a student account, active session cookies are terminated immediately, blocking concurrent in-flight transactions.
