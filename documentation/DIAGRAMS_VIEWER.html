Model-Template-View (MTV) Architecture Diagram

Demonstrates request dispatching, two-role RBAC routing, atomic services, and server-rendered templates.
flowchart TD User([Browser Client]) -->|HTTP Request| URLConf[Django URL Dispatcher urls.py] URLConf -->|/manage/*| AdminMW[AccountActiveCheckMiddleware & @admin_required] URLConf -->|/portal/*| UserMW[AccountActiveCheckMiddleware & @user_required] AdminMW --> AdminViews[Custom Admin Views admin_views.py] UserMW --> UserViews[Basic User Views user_views.py] AdminViews --> Services[Domain Services services.py: Interval Math & Atomic Locking] UserViews --> Services Services --> Models[ORM Models models.py: select_for_update & atomic] Models --> DB[(SQLite Database db.sqlite3)] Models --> TemplateContext[Context Processor & Model Data] TemplateContext --> Templates[Templates: base_admin.html / base_user.html] Templates -->|Rendered HTML / CSV| User
Key Architectural Highlights: Pure server-rendered MTV pattern. Prohibits Django's built-in admin by routing `/manage/` to custom-coded administrative views, protected by session-invalidating active checks.

Diagram 3

Reservation Lifecycle State Machine Workflow

Finite state machine detailing valid state transitions, check-in validation, and terminal states.
stateDiagram-v2 [*] --> PENDING : User Submits Reservation Request PENDING --> APPROVED : Admin Approves (Atomic Lock & Conflict Check) PENDING --> REJECTED : Admin Rejects (Reason Mandatory) PENDING --> CANCELLED : User Cancels (Prior to Start Time) APPROVED --> CHECKED_IN : Admin Records Physical Arrival on Event Day APPROVED --> CANCELLED : User / Admin Cancels (Prior to Start Time) APPROVED --> NO_SHOW : Event End Passed Without Check-In CHECKED_IN --> COMPLETED : Admin Concludes Event & Inspects Venue REJECTED --> [*] CANCELLED --> [*] NO_SHOW --> [*] COMPLETED --> [*]
Business Rules Enforced: 1. Requests start as `PENDING` (no slot reserved). 2. Only `APPROVED` events can be checked in. 3. Events cannot reach `COMPLETED` without prior check-in. 4. Terminal states (`COMPLETED`, `REJECTED`, `NO_SHOW`, `CANCELLED`) cannot be arbitrarily reopened.
